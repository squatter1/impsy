\section{Monte-Carlo Tree Search}
The core component of our system is the use of search to generate predictions. For this, a Monte Carlo Tree Search (MCTS) algorithm is used as the basis for generating and searching these prediction trees. MCTS is a heuristic search algorithm for decision processes, most notably employed in game playing and planning.

MCTS builds a search tree incrementally and asymmetrically, focusing on the most promising parts of the search space. The algorithm consists of four main steps: selection, expansion, simulation, and backpropagation.

\begin{itemize}
    \item \textbf{Selection:} Starting from the root node, the algorithm selects successive child nodes until a leaf node is reached. The selection is based on a policy that balances exploration and exploitation, typically using the Upper Confidence Bound for Trees (UCT) formula.
    \item \textbf{Expansion:} If the leaf node is not a terminal state, one or more child nodes are generated and added to the tree.
    \item \textbf{Simulation:} A simulation (or playout) is run from the newly added node to a terminal state, using a default policy to make decisions.
    \item \textbf{Backpropagation:} The result of the simulation is propagated back through the tree, updating the nodes' statistics.
\end{itemize}

By iterating these steps, MCTS gradually builds a search tree and improves its predictions. The algorithm's effectiveness comes from its ability to focus computational resources on the most promising parts of the search space, making it well-suited for complex decision-making tasks. Additionally, as shown in the related work section, MCTS has been successfully applied in combination with MDNs in other domains, particularly robot navigation problems such as self driving cars, and has seen success. To apply MCTS to the predicition system of IMPSY, some notable challenges need to be addressed and accounted for.

Firstly, the search space of a musical piece does not have a terminal state, as unlike a game with a clear win or loss condition, a musical piece can, and in the case of IMPSY is assumed to, continue indefinitely. This means that the simulation step of MCTS cannot be run to a terminal state, and instead must be run for a set number of steps. In a basic implementation this can be a fixed number of steps, however for our system we allow the depth of search to be variable based on the 1. how promising this branch of the search tree is, and 2. how much the heuristic value appears to change with increased depth. This allows the system to focus computational resources on the most promising parts of the search space, and to avoid wasting resources on branches that are unlikely to yield useful improvements to predictions. For our Continuous Monte-Carlo Tree Search (C-MCTS) implementation, we use progressive widening. Progressive widening gradually adds children to nodes as they are visited more often, allowing the search tree to grow in a controlled manner. In particular, our version of progressive widening selects from a modified GMM produces as an MDN output, and if the result is more than $\epsilon$ away from any existing child nodes, a new child node is added, otherwise the existing child node with the closest value is selected.

We have chosen this technique because progressive widening is simple in that it maintains a discrete search tree. Mixture Density Network outputs were originally used in IMPSY because of the benefit that a small amount of randomness provides in making the system sound more human and natural in its improvisation, and by rounding similar MDN outputs into the same discrete action in the search tree, we can maintain the benefits of this randomness, whilst also controlling it in a way which allows for musical structure.

When using C-MCTS, instead of taking a single MDRNN prediction at each step and choosing randomly from the resulting distribution, the C-MCTS algorithm generates a tree of possible future musical directions for the piece, and hence allows for heuristics to be applied in selecting the most promising direction to take according to set structural parameters. This allows for the system to make more informed decisions about the future of the piece, and to generate more structured and coherent improvisations.

\section{Heuristics}
For the C-MCTS algorithm to be useful, it must be guided by heuristics which provide useful benefit to the output of the system. In the case of IMPSY, we have developed a set of structural parameters which can be used to guide the system in generating more structured and coherent improvisations. These structural heuristics are based on the principles of music theory, and are intended to help describe the current playing style of the human performer and the current state of the piece, and hence guide the system in generating more appropriate predictions which coherently follow the current state of the piece.

Note here the limitation of heuristics needing to be defined independently for different instruments, with a few core exceptions such as purely timing based heuristics like tempo. This is because the same parameter can have different meanings for different instruments, eg pitch variation for a drum kit vs a guitar. And some instruments have more dimensions in their output than others, which for each instrument can control various different things. Introduce the standard we will be using for the rest of the paper, which is a 2-dimensional keyboard output: with one pitch dimension and one time dimension. The heuristics should hence be translatable to any instrument with clear continuous pitch and time dimensions to their output, but instruments with higher dimensionality would benefit from adding more, and more complex, heuristics which account for these extra dimensions.

\subsection{Setting Heuristics Through Human Performance}
By default, for each heuristic, the system tracks both the value of the heuristic, and the rate of change of the heuristic, being its derivative with respect to time. Higher order derivatives can also be added to track more complex patterns of change in these values. In this way, the system tracks useful metrics about the the state of the piece, and then can replicate these patterns when it takes over in its improvisation.

\subsection{Utilising Heuristics for Prediction}
When the system takes over from a human performer in an improvisation, it forecasts the future values of each structural parameter based on 1. the current value of the parameter, 2. derivatives of the parameter, and 3. identified repeating pattern of the parameter. A heuristic can then be created from the forecasted values, where the heuristic value at a given node is its euclidean distance from the forecasted value vector at that point in time. The length of memory used to generate the values of the parameters must at minimum be the depth of the search tree at the point of the evaluated node.
